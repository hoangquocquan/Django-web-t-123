# Production Evidence Package Structure

## Purpose

This document defines the expected file structure for handing over production
IIS evidence to the migration reviewer.

## Directory Layout

```text
production_evidence/
├── input/
│   ├── iis_logs/
│   │   └── u_ex*.log
│   └── iis_api_evidence.csv
├── reports/
│   └── REAL_PRODUCTION_EVIDENCE_REPORT.json
└── handover/
    └── collection_metadata.json
```

## Input Files

`input/iis_logs/u_ex*.log`

Raw IIS W3C logs or reviewed copies. Store outside Git if sensitive.

`input/iis_api_evidence.csv`

Sanitized API traffic export with this header:

```text
timestamp,source,client,endpoint,status_code,user_agent
```

## Report Files

`reports/REAL_PRODUCTION_EVIDENCE_REPORT.json`

Machine-readable evidence report generated by the collection or acceptance
validator.

## Handover Files

`handover/collection_metadata.json`

Metadata proving the collection source, period, operator and reviewer.

## Acceptance Rule

The package is accepted only when:

- IIS logs exist.
- Metadata exists and has required values.
- Collection period exists.
- IIS logs contain required W3C fields.
- CSV exists and has at least one data row.
- Legacy `/api/*` traffic is `0`.
- Django `/api/v1/*` traffic is greater than `0`.
- Unknown clients are `0`.
